# Glossary

| Term | Meaning |
| --- | --- |
| SPEC-FORGE | Specification-driven development governance used in this repository. |
| Spec | Human-reviewed behavioral contract; draft is not implementation permission. |
| AC | Numbered acceptance criterion local to a spec (AC-1, AC-2, …). |
| ADR | Immutable accepted decision; changes require a superseding decision. |
| Task | One reviewable work unit, with spec/plan references and verification command. |
| Ledger | Append-only record of session work and actual verification. |
| State | Replaceable snapshot for the next session. |
| Trace | Exact links between specs, tasks, files, tests, branches, and evidence. |
| Legacy reference | Untouched architecture provenance; formal APPROVED derivatives are SPEC-001–SPEC-004. |
| DAW | Digital audio workstation. |
| DSP | Digital signal processing. |
| EDL | Non-destructive edit decision list described by the architecture reference. |
